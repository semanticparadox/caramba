# Paypalych (pally.info) — пошаговая инструкция до получения токена

> Краткий план: создать проект в кабинете pally.info → заполнить анкету
> корректно → дождаться модерации (1–3 рабочих дня) → забрать API Token +
> Shop ID → вставить в caramba panel (`/admino4ka/settings` → Paypalych).

---

## 0. Предусловие

- У тебя уже есть аккаунт на **pally.info** (email: `ayertag@gmail.com`).
- Панель caramba уже задеплоена и доступна по `https://panel.exarobot.top` (это **публичный** домен, важно для webhook — Pal24 до него достучится).
- Панель уже на **v0.9.52+** (там появилась карточка Paypalych в Settings).

## 1. Создание проекта в кабинете Pal24

1. Логин на [pally.info](https://pally.info) → раздел **«Проекты»** (или «Магазины» — UI менялся) → **«Создать проект» / «Добавить»**.
2. Откроется анкета. Заполняй по разделам ниже — я вытащил значения под caramba из твоих настроек.

### Поля анкеты

| Поле | Что вписать | Почему |
|---|---|---|
| **Название проекта** | `Caramba VPN` | Как у тебя на фронте, чтобы клиент видел знакомое имя. |
| **Тип деятельности** | `IT / Хостинг / VPN-сервис` или `Информационные технологии` | Pal24 разделяет по рискам; VPN/IT обычно одобряют без вопросов. Если есть выпадающий список с подкатегориями — выбирай ближайшее к «информационный сервис / подписочный сервис». |
| **Описание** | `Подписочный VPN-сервис на базе sing-box. Клиенты оплачивают доступ через СБП и USDT TRC20. Услуга оказывается в цифровом виде, без физической доставки.` | Коротко, по делу. Без «заработок», «инвестиции», «крипто» — триггерит скоринг на отказ. |
| **Язык интерфейса магазина** | `Русский` | Основная аудитория RU. |
| **URL магазина (Site URL)** | `https://panel.exarobot.top` | Публичный домен твоей панели. Можно ещё указать `https://app.exarobot.top` (Mini App), но основной — панель. |
| **Success URL** (куда клиент после успешной оплаты) | `https://t.me/exa_robot` | Возврат в Telegram-бот — стандартный UX для caramba. |
| **Fail URL** (куда при отмене/ошибке) | `https://t.me/exa_robot` | Тот же бот. Можно тот же URL, Pal24 не различает. |
| **Result URL** (webhook для всех уведомлений) | `https://panel.exarobot.top/api/webhooks/payment/paypalych` | Панель ловит все события (paid/canceled/expired). |
| **Refund URL** | `https://panel.exarobot.top/api/webhooks/payment/paypalych` | Тот же — панель разруливает по полю `status` в теле. |
| **Chargeback URL** | `https://panel.exarobot.top/api/webhooks/payment/paypalych` | Тот же. |

> ⚠️ Все три URL-нотификации (Result / Refund / Chargeback) **должны быть одинаковые** — иначе Pal24 не отправит refund/chargeback события в твой обработчик.

3. Подтверди создание. Pal24 должен показать плашку «Проект создан» и перевести в статус **«На модерации»**.

## 2. Что делать пока идёт модерация (1–3 рабочих дня)

- В кабинете pally.info можно уже сейчас зайти в **«API интеграция»** созданного проекта и убедиться, что **API Token** отображается (формат `72|xxxxxxx...`). Если ещё нет — это нормально, токен обычно появляется вместе с одобрением.
- **НЕ** включай тумблер `paypalych_enabled` в caramba до того, как проект одобрят. Панель стартует с токеном нормально, но реальные платежи не пройдут — будет путаница.
- Можно поставить cron в голове проверить через 1–2 дня (вкладка «Проекты» → статус сменится с «На модерации» на «Активен»).
- Если **>3 рабочих дней** нет ответа — пиши в поддержку Pal24 (обычно Telegram-бот или email в личном кабинете). Часто достаточно напомнить.

### Что Pal24 может попросить дополнительно (типичные запросы)

- Скан/фото паспорта (разворот + прописка) — это нормально, готовь заранее.
- Селфи с паспортом — реже, но бывает.
- Скриншот сайта/панели по указанному Site URL. У тебя это `panel.exarobot.top` — там сейчас заглушка Cloudflare, и это **может быть проблемой**. Если попросят — сделай скриншот Mini App (`https://app.exarobot.top` — основной продукт для клиента) и поясни, что `panel.exarobot.top` это admin-панель управления, а `app.exarobot.top` — клиентский интерфейс.
- Выписка с банка или скрин Payeer/ЮMoney с балансом — почти никогда не просят для подписочных IT-сервисов на СБП.
- **Что НЕ просят** (и что точно не нужно слать самому): сканы кредитных карт, логины/пароли от чего-либо, скрины биржевых аккаунтов.

## 3. После одобрения — забрать креды

1. Кабинет pally.info → **«Проекты» → Caramba VPN → «API интеграция»** (или «Настройки → API»).
2. Скопируй **API Token** (формат `72|xxxxxxx...`). Храни в менеджере паролей.
3. Скопируй **Shop ID** — это числовой ID проекта, виден в URL: `https://pally.info/projects/12345/...` → `12345` это Shop ID. Если у тебя один проект на этот токен, **Shop ID можно оставить пустым**.

> ⚠️ **Важно (v0.9.53+)**: поля «Webhook Secret» в карточке Paypalych в админке больше **нет** — Pal24 подписывает webhook через сам API-токен по формуле `strtoupper(md5(OutSum:InvId:api_token))`. В v0.9.52 поле существовало, но это была ошибка (Pal24 его не использует); с v0.9.53 поле удалено из UI. Старое значение, если осталось в БД, игнорируется.

## 4. Прописать в caramba panel

1. Открой `https://panel.exarobot.top/admino4ka/settings` (или твой `ADMIN_PATH`).
2. Прокрути до раздела **«Платежи»**.
3. Найди карточку **«Paypalych»** 🇷🇺 (с подзаголовком «СБП · USDT TRC20 · для РФ-аудитории»).
4. Поставь галочку **«Включён»** (toggle в левом верхнем углу карточки — он подсветится зелёным).
5. Заполни:
   - **API Token** → вставь `72|xxxxxxx...` (поле автоматически замаскируется при сохранении). Этот токен используется и для аутентификации, и для проверки подписи webhook.
   - **Shop ID** *(опционально)* → вставь число, если оно у тебя есть.
6. Нажми синюю кнопку **«Сохранить»** в самом низу страницы (она общая для всех настроек).
7. После сохранения нажми **«Проверить подключение»** прямо в карточке Paypalych — панель попробует создать тестовый инвойс на 0.01 ₽ через Pal24 API. Если зелёная галочка — креды валидные, всё подключено.

## 5. Smoke test (опционально, но рекомендую)

Перед тем как анонсировать Paypalych клиентам:

1. Создай в Mini App тестовый инвойс на 10 ₽ (СБП-минимум). Оплати сам через свой СБП.
2. В админке → **«Logs»** → должны увидеть запись `Webhook processed successfully` для `paypalych`.
3. В разделе **«Платежи / Транзакции»** — статус инвойса должен стать `paid`, подписка активироваться.
4. Повтори с USDT TRC20 на 400 ₽ (минимум). Те же шаги, только через `https://app.exarobot.top` будет оплата криптой.

Если оба прошли — провайдер готов к боевым платежам. **Перед боем не забудь** переключить тумблер в панели в положение «Показывать клиентам» (это `paypalych_enabled` toggle → ещё раз убедись что true; и в разделе **«Способы оплаты и цены»** (`/admino4ka/payment-pricing`) — поставь галочку напротив Paypalych, чтобы он появился в Mini App).

## 6. Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| API Token не появляется в кабинете после одобрения | Напиши в поддержку Pal24. Иногда нужно регенерировать токен вручную. |
| `Проверить подключение` вернул `Authentication failed` | Скоре всего токен скопирован с пробелом/переносом. Скопируй заново, проверь. |
| Webhook не доходит до панели | Проверь что `https://panel.exarobot.top/api/webhooks/payment/paypalych` отвечает 200 снаружи (curl из другого хоста). Проверь что в кабинете Pal24 в полях Result/Refund/Chargeback стоит **именно этот** URL, а не какой-то старый. |
| `Подпись не совпадает` | В Pal24 нет отдельного webhook secret — подпись вычисляется как `strtoupper(md5(OutSum:InvId:api_token))`, где `api_token` это API Token из карточки. Убедись что в поле «Paypalych API Token» вставлен именно тот токен, что в pally.info → API интеграция. В v0.9.52 в админке было отдельное поле Webhook Secret — оно игнорируется начиная с v0.9.53. |
| Клиент оплатил, но подписка не активировалась | Открой `/admino4ka/nodes/reload-all` чтобы панель проверила статусы через polling. Или в БД посмотри `payment_sessions` — должен быть `status=paid`. Если `pending` — webhook не дошёл. |
| Клиент видит Paypalych в Mini App, но не может оплатить | Проверь что в `/admino4ka/payment-pricing` → Paypalych включён и у него есть override-цена для текущего плана/длительности (если хочешь не-USD валюту). |

## 7. После запуска

- Включи в админке **уведомления в Telegram** про failed payments (раздел «Уведомления» в Settings → триггер «payment failed»).
- Мониторь первые дни статистику в Pal24: % отмен, средний чек, время от оплаты до webhook.
- Если через 2 недели увидишь >5% chargeback — Pal24 начнёт звонить; подготовь refund-флоу заранее (он у нас уже есть в `fulfill_payment`).
- Когда наберёшь статистику — пересмотри тарифы. СБП 6.5% + 2₽ кусается; USDT 3% + 1 USDT — норм.
