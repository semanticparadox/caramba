Paypalych (pal24.pro / pally.info) — СБП и USDT TRC20

Российский платёжный сервис, заточенный под RU-аудиторию: СБП (Система быстрых платежей) и USDT TRC20. Удобен тем, что умеет оба канала в одной интеграции — вы выдаёте клиенту ссылку, он выбирает способ оплаты. Аутентификация — Bearer-токен, webhook подписывается MD5 от тела (обязательно, отключить нельзя).

Для РФ KYC: лёгкий Комиссия: СБП 6.5% · USDT 3% СБП · USDT TRC20

Когда подойдёт

  • Большая часть ваших клиентов в РФ и платит в рублях через СБП — это основной канал, дешевле карт.
  • Хотите принимать и крипту (USDT TRC20) через тот же API — удобно, если часть аудитории в крипте.
  • Не хотите возиться с разными провайдерами на каждый канал — Pal24 закрывает оба.

Тарифы (на момент интеграции)

  • СБП: 6.5% + 2 ₽, минимум 10 ₽, максимум 50 000 ₽ за инвойс.
  • USDT TRC20 в ₽: 3% + 1 USDT, минимум 400 ₽, максимум 1 000 000 ₽ за инвойс.

Регистрация

  1. Откройте pally.info и зарегистрируйтесь (email, телефон).
  2. Подтвердите email.
  3. В личном кабинете создайте проект: Проекты → Создать. Заполните анкету: название, тип деятельности, описание, язык, URL магазина, Success URL, Fail URL, Result URL, Refund URL, Chargeback URL. Все три webhook-URL укажите одинаковые — обработчик один, разруливает по полю status в теле.
  4. Дождитесь модерации (обычно 1–3 рабочих дня).

Где взять ключи

  1. После одобрения проекта перейдите: Проекты → ваш проект → API интеграция.
  2. Скопируйте API Token — выглядит как 72|xxxxxx... (формат Laravel Sanctum).
  3. Shop ID (числовой идентификатор проекта) — виден в URL проекта: /projects/<shop_id>. Опционально: если у вас один проект на этот токен, можно оставить поле пустым.
  4. Вставьте API Token в поле «Paypalych API Token» (paypalych_api_token) в настройках панели. Этот же токен используется для подписи webhook — отдельного секрета нет.
  5. Вставьте Shop ID (число) в поле «Paypalych Shop ID» (paypalych_shop_id) — если он у вас есть.

Webhook URL

При создании проекта вы указали Result/Refund/Chargeback URL. Все три должны вести на:

{{ panel_url }}/api/webhooks/payment/paypalych

Один обработчик обслуживает все три типа нотификаций. Если уже создали проект с другими URL — отредактируйте в кабинете Pal24.

Подпись webhook

Pal24 подписывает webhook в теле запроса (не в заголовке). Тело приходит как application/x-www-form-urlencoded с полями Status, InvId, OutSum, CurrencyIn, TrsId, custom и SignatureValue.

Формула подписи:

strtoupper(md5(OutSum + ":" + InvId + ":" + api_token))

Где api_token — это тот же API Token из pally.info (Bearer-токен в формате 72|xxxxxx...). Отдельного webhook-секрета в Pal24 нет — для подписи используется сам API-токен. Панель проверяет подпись автоматически, никаких дополнительных полей заполнять не нужно.

В версии панели v0.9.52 поле «Webhook Secret» в карточке Paypalych было ошибкой (Pal24 его не использует) и начиная с v0.9.53 удалено из UI. Если у вас в базе осталось заполненное значение — оно просто игнорируется, можно очистить через SQL.

Особенности

  • Все инвойсы создаются в валюте RUB — Pal24 сам делает конвертацию в USDT, если клиент выбрал крипту.
  • Клиент после оплаты возвращается на Success URL из настроек магазина (по умолчанию Telegram-бот). Панель success_url/fail_url per-call не передаёт — используется дашборд-конфиг.
  • Статусы webhook (PascalCase): SUCCESS (успех), FAIL (неуспех), NEW / MODERATING (открыт). Панель маппит их на свои Completed / Failed / Pending.
  • Polling-fallback (check_status) пока не реализован — webhook-loss полагается на 1-2 ретрая от провайдера + ручное подтверждение через админку. Если станет проблемой, добавим GET /bill/status отдельным тикетом.

Тестирование

  1. После сохранения токена нажмите кнопку «Проверить подключение» на карточке Paypalych — панель попробует создать тестовый инвойс на 0.01 ₽ через Pal24 API. Успех = креды валидные.
  2. Создайте реальный тестовый инвойс в Mini App на минимальную сумму (10 ₽ через СБП или 400 ₽ через USDT).
  3. Оплатите его сами, проверьте что webhook дошёл до панели (раздел Logs в админке) и подписка активировалась.

Возможные проблемы

  • «Authentication failed» → токен скопирован не полностью, или проект ещё не одобрен модерацией. Проверьте кабинет Pal24.
  • «Shop not found» → Shop ID указан неверно, либо для этого токена он не нужен (оставьте поле пустым).
  • Webhook не приходит → URL в кабинете Pal24 должен указывать на {{ panel_url }}/api/webhooks/payment/paypalych дословно. Панель должна быть доступна снаружи по HTTPS. Проверьте Result / Refund / Chargeback URL — все три должны вести на один адрес.
  • Подпись не совпадает → панель вычисляет подпись как strtoupper(md5(OutSum:InvId:api_token)) и сверяет с полем SignatureValue в теле. Убедитесь, что в карточке заполнен именно API Token (тот же, что в заголовке Authorization: Bearer), а не старое значение Webhook Secret из v0.9.52.
  • Проект на модерации → токен уже виден в кабинете, но реальные платежи не пройдут. Дождитесь подтверждения.
