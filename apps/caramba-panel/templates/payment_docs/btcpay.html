BTCPay Server — самохостинг, ноль KYC, ноль комиссий

Открытый self-hosted Bitcoin и крипто-процессинг. Никаких посредников, никакой верификации личности, никаких комиссий (кроме blockchain fee). Нужен VPS для установки.

Крипта KYC: нет Комиссия: 0% (только blockchain fee) BTC · LN · USDT · и другие (зависит от плагинов)

Когда подойдёт

  • Максимальная приватность и независимость от сторонних сервисов — ваш сервер, ваши ключи.
  • Нулевые комиссии (только транзакционные сборы сети) при больших объёмах.
  • Принципиальный отказ от KYC — BTCPay Server не хранит данные о платежах на чужих серверах.
  • Технически подготовленный администратор — требуется Docker и свой VPS.

Установка BTCPay Server

  1. Арендуйте VPS (минимум 2 CPU, 4 GB RAM, 100 GB SSD) у любого зарубежного хостинга. Подойдут Hetzner, DigitalOcean, Vultr, OVH.
  2. На сервере выполните официальный установочный скрипт: 
    curl -sSL https://raw.githubusercontent.com/btcpayserver/btcpayserver-docker/master/btcpay-setup.sh -o btcpay-setup.sh
chmod +x btcpay-setup.sh
export BTCPAY_HOST="pay.your-domain.com"
export NBITCOIN_NETWORK="mainnet"
export BTCPAYGEN_CRYPTO1="btc"
export BTCPAYGEN_REVERSEPROXY="nginx"
export BTCPAYGEN_LIGHTNING="lnd"
. ./btcpay-setup.sh -i
  3. Настройте DNS: создайте A-запись для домена pay.your-domain.com, указывающую на IP вашего VPS.
  4. Дождитесь синхронизации Bitcoin-ноды (занимает от нескольких часов до 1–2 дней).
  5. Откройте https://pay.your-domain.com — зарегистрируйтесь как первый администратор.

Где взять ключи

  1. В BTCPay Server войдите как администратор → перейдите в ваш Store.
  2. Скопируйте Store ID: Store → Settings → General → Store ID.
  3. Создайте API Key: Account → API Keys → Generate Key. Выберите нужные права (минимум: Create Invoice, View Stores). Скопируйте ключ.
  4. Создайте Webhook (см. ниже) — при создании BTCPay покажет Webhook Secret.
  5. Вставьте в настройки панели:
    • URL вашего BTCPay → «BTCPay URL» (btcpay_url), например https://pay.your-domain.com
    • API Key → «BTCPay API Key» (btcpay_api_key)
    • Store ID → «BTCPay Store ID» (btcpay_store_id)
    • Webhook Secret → «BTCPay Webhook Secret» (btcpay_webhook_secret)

Webhook URL

Добавьте в BTCPay Server следующий URL для уведомлений:

{{ panel_url }}/api/webhooks/payment/btcpay

Где настроить: Store → Settings → Webhooks → Create Webhook. Вставьте URL выше. Выберите событие InvoiceSettled (и InvoiceExpired для отслеживания истёкших счетов). Скопируйте показанный Secret.

Особенности

  • Проверка подписи: заголовок BTCPay-Sig в формате sha256=<hex>. HMAC-SHA256 от raw body с вашим Webhook Secret. Панель проверяет автоматически.
  • Синхронизация полной Bitcoin-ноды занимает время и дисковое место (~650 GB для mainnet). Для экономии используйте Pruned Mode или подключитесь к удалённой ноде.
  • Lightning Network доступна для мгновенных и дешёвых транзакций — требует дополнительной настройки LND-ноды в BTCPay.
  • BTCPay Server — открытый код (MIT лицензия). Регулярно обновляйте через btcpay-update.sh для безопасности.

Тестирование

  1. В BTCPay Server перейдите в Store → Settings → General → Bitcoin и переключитесь на Testnet или Regtest.
  2. В режиме Regtest вы можете сами генерировать тестовые монеты командой bitcoin-cli -regtest generatetoaddress 101 <ваш адрес>.
  3. Создайте тестовый инвойс через панель и оплатите с тестового кошелька (Electrum, BlueWallet с testnet).

Возможные проблемы

  • Webhook не приходит → убедитесь, что URL панели доступен из интернета. BTCPay должен иметь возможность делать HTTPS-запросы к вашей панели.
  • Подпись не совпадает → убедитесь, что Webhook Secret скопирован из BTCPay при создании webhook — после этого он не отображается повторно (создайте новый, если потеряли).
  • Нода не синхронизируется → проверьте наличие места на диске. Используйте docker logs btcpayserver_bitcoind для диагностики.
  • BTCPay недоступен после перезагрузки сервера → убедитесь, что Docker настроен на автозапуск: systemctl enable docker. BTCPay запускается автоматически через Docker Compose.
