# caramba_vpn

Federated Flutter plugin that gives the exarobot client a real native VPN
tunnel. It registers the platform channels the app already consumes and bridges
them to the caramba-core Go engine (mihomo): a gomobile `aar`/`xcframework` on
mobile, a cgo c-shared `libcaramba_core` on desktop.

User-facing brand is `exarobot`. Code identifiers stay `caramba` (package name
`caramba_vpn`, channels `com.caramba/vpn`, the plugin classes below). Do not
rename them. They are the federation and panel/client contract.

## What lives here

This package owns its root only: `pubspec.yaml`, `lib/`, `analysis_options.yaml`
and this README. The native folders (`android/`, `ios/`, `macos/`, `windows/`,
`linux/`) are owned and filled by the platform tasks. The app's
`android/ios/macos/windows/linux` folders are generated by `flutter create .`
and are not committed, so all native tunnel code lives inside this plugin to
survive regeneration. App-level glue that cannot live in a plugin (Android
manifest VPN service plus permission, the iOS/macOS Network Extension target,
entitlements, App Group, desktop privilege elevation) is described in the
project `INTEGRATION.md` and applied after `flutter create .`.

The Dart side is intentionally thin. The tunnel lifecycle already belongs to the
app, in `lib/vpn/vpn_service.dart` (`MethodChannelVpnConnection`). This plugin
adds exactly one thing on top of that contract: a `configure` call so the app
can hand the auth and config seam to native before the first `connect`.

## Channel contract (registered by every platform class)

MethodChannel `com.caramba/vpn`:

- `connect({ serverId: String, serverName: String, countryCode: String })` -> void
- `disconnect()` -> void
- `status()` -> optional current status map
- `configure({ panelUrl: String, subscriptionId: String, accessToken: String })` -> void

EventChannel `com.caramba/vpn/status` emits a map:

- `{ stage: String, detail: String?, connectedSinceMs: int }`
- `stage` is one of exactly: `disconnected`, `connecting`, `connected`,
  `reconnecting`, `error` (lowerCamel, matches the Dart `VpnStage` names).

EventChannel `com.caramba/vpn/traffic` emits a map:

- `{ downBps: int, upBps: int, downTotal: int, upTotal: int }`

The native side drives the stage transitions and emits a traffic tick at about
1 Hz while connected, and zeros or `disconnected` otherwise.

## Auth and config seam (`configure`)

`configure` maps onto the caramba-core mobile facade
(`libs/caramba-core/mobile/mobile.go`) and the desktop cgo entry points:

1. `panelUrl` -> `mobile.NewClient(panelUrl, subURL, workDir, tokenPath)`
   (build or reuse the per-process `Client`).
2. `accessToken` -> write into the engine token store so config and
   subscription requests go out authorized. The token store struct is
   `auth.Tokens` (`access_token`, `refresh_token`, `access_expiry`); a refresh
   token may not be present yet on the seam, so persist what is given and let
   the panel issue a refresh pair on first 401.
3. `subscriptionId` -> `client.SetSubscriptionID(subscriptionId)`. Empty means
   the core resolves the UUID from the panel lazily.

Call `configure` before `connect`. It is idempotent: the app calls it again
after a token refresh to update the seam.

## Native TUN handoff (for the platform tasks)

The Go engine takes the TUN file descriptor the platform creates and runs the
mihomo data path over it. AmneziaWG is one of the protocols the core selects
(friendly name `AmneziaWG`, see `mobile.SetProtocol`); the panel-built
proxy-group selector is `profile.CarambaSelector` (`"CARAMBA"`) and must not be
renamed.

- Android: `VpnService.Builder.establish().detachFd()` -> `client.SetTunFd(fd)`.
- iOS / macOS: `NEPacketTunnelProvider` `tunnelFileDescriptor` -> `SetTunFd`.
- Windows: wintun adapter via `libcaramba_core.dll` (bundle `wintun.dll`).
- Linux: TUN device via `libcaramba_core.so`.

## Federation map (platform classes the platform tasks must implement)

| Platform | pubspec key | pluginClass | language / package |
| --- | --- | --- | --- |
| Android | `android` | `CarambaVpnPlugin` | Kotlin, package `com.caramba.caramba_vpn`; plus VPN service `CarambaVpnService` extending `android.net.VpnService` |
| iOS | `ios` | `CarambaVpnPlugin` | Swift; plus `PacketTunnelProvider` (`NEPacketTunnelProvider`), extension target is app-level |
| macOS | `macos` | `CarambaVpnPlugin` | Swift, shares the iOS `NEPacketTunnelProvider` approach |
| Windows | `windows` | `CarambaVpnPluginCApi` | C++, loads `libcaramba_core.dll`, bundles `wintun.dll` |
| Linux | `linux` | `caramba_vpn` | C++/GObject, loads `libcaramba_core.so` |

## Usage

```dart
import 'package:caramba_vpn/caramba_vpn.dart';

await CarambaVpn.instance.configure(
  panelUrl: 'https://panel.example',
  subscriptionId: subscriptionUuid,
  accessToken: jwtAccessToken,
);
// connect/disconnect/status stay on the app's MethodChannelVpnConnection.
```

The app depends on this package by path:

```yaml
dependencies:
  caramba_vpn:
    path: packages/caramba_vpn
```
