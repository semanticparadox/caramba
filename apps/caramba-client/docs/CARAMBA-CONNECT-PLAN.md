# Caramba Connect — план B2B-разворота (исполняемая спецификация)

Этот файл — источник истины для автономного ultracode-прогона. Он превращает
односервисный VPN (exarobot) в платформу: универсальный клиент Caramba Connect +
панель, продаваемая операторам как self-hosted инстанс под лицензией.

Связанная память: `caramba-connect-platform`, `caramba-client-app`, `no-ai-slop`.
Всё пишется статически (в песочнице нет go/cargo/flutter); панель = источник
истины по контрактам, клиенты подгоняются. Паттерн на каждую фазу:
recon (только чтение) -> build (непересекающиеся директории) -> состязательное
ревью -> fix. Контракты пиннятся в этом файле, чтобы параллельные слои сходились.

## 1. Видение и зафиксированные решения

- Универсальный бесплатный клиент **Caramba Connect** (аналог Hiddify): по
  умолчанию нейтральный стиль платформы.
- Два режима подключения: (a) сырая sub-ссылка (sing-box/clash/v2ray, без
  аккаунта); (b) подключение к панели по enrollment/login-ссылке (аккаунт нужен),
  с опциональной white-label темой от этой панели.
- Продаём **self-hosted инстансы панели** под лицензией. Оператор приносит свои
  ноды. exarobot = первый тенант (tenant #1), сохраняет бота @exarobot.
- Бренд: **Caramba Connect** = пользовательский бренд платформы/приложения;
  exarobot = бренд тенанта #1; per-tenant бренды настраивают операторы. Код-иды
  остаются `caramba`; `profile.CarambaSelector = "CARAMBA"` (контракт панель<->
  клиент) не менять. ANTI-SLOP применяется ко всем брендам.

## 2. Лицензионные тиры (операторская подписка за право крутить панель)

Цена — это то, что ОПЕРАТОР платит владельцу платформы за лицензию на инстанс,
НЕ цена для конечного пользователя.

| Тир  | Ноды | Юзеры | End-user биллинг | Брендинг | Реклама Caramba Connect | Цена |
|------|------|-------|------------------|----------|-------------------------|------|
| Free | 2    | 100   | выключен (админ вручную подтверждает выдачу конфига) | нельзя | показывается | $0 |
| Pro  | высокий дефолт (1000, настраивается) | высокий дефолт (настраивается) | можно включить | можно | нет | 3 мес $40 / 6 мес $70 / 12 мес $120 |

Дефолты-константы выносятся в одно место (легко править). v1 = Free + Pro.
Промежуточные тиры — задел на будущее, сейчас не строим.

Матрица ограничений (enforcement) применяется панелью на основе активной
лицензии: `max_nodes`, `max_users`, `end_user_billing_enabled`,
`branding_enabled`, `upstream_ads_enabled`, `manual_approval_required`.

## 3. Архитектура (слои)

- **Control plane (тонкий лиценз-сервер)**: выдаёт/валидирует лицензионные ключи,
  отдаёт тир + срок. Минимальный HTTP-сервис (может жить как отдельный bin-crate
  или режим панели). Активация при старте панели + периодически.
- **Tenant panel (инстанс)**: текущая панель caramba + лицензионный гейтинг +
  `/app/branding` + onboarding-трафик. Ставится инсталлером с лицензионным ключом.
- **Per-instance бот**: текущий бот, обобщённый под (токен бота + URL панели) на
  деплой. exarobot-бот = конфиг тенанта #1.
- **Универсальный клиент Caramba Connect**: мульти-профиль (сырые подписки +
  панель-аккаунты), импорт всех актуальных форматов, рантайм-темизация от активной
  панели, дефолт = стиль Caramba Connect.

## 4. Новые примитивы и контракты (пиннятся здесь)

### 4.1 Лицензия/активация
- `POST {LICENSE_SERVER}/v1/activate { license_key, instance_id, version }` ->
  `{ tier: "free"|"pro", expires_at, limits: { max_nodes, max_users,
  end_user_billing, branding, upstream_ads, manual_approval }, signature }`.
- Панель кеширует ответ, проверяет подпись (ed25519), повторяет проверку раз в
  ~12-24ч. **Грейс офлайн**: если сервер недоступен, действует последний валидный
  ответ ещё N дней (дефолт 14), затем мягкая деградация (НЕ блокировать
  существующих юзеров; блокировать только включение биллинга/брендинга/добавление
  нод сверх лимита). Free-инстанс не требует ключа (тир по умолчанию = free).
- `instance_id` генерируется при установке. Ключ задаётся инсталлером.

### 4.2 /app/branding (white-label, тир-гейт)
- `GET /api/v2/app/branding` (публичный, без JWT — нужен до логина) ->
  `{ enabled: bool, brand_name, logo_url, accent_hex, support_url, bot_url,
  upstream_ads: bool }`. На Free-тире `enabled:false` + `upstream_ads:true`
  (клиент рисует дефолт Caramba Connect + промо-блок «powered by / upgrade»).
  Акцент валидируется под анти-слоп (не фиолет/градиент; один высококонтрастный
  акцент; цвет статуса остаётся за подключением). Брендинг настраивается
  оператором (см. фазу P3 — где именно).

### 4.3 Enrollment-ссылка (подключение к панели, аккаунт обязателен)
- Диплинк `carambaconnect://enroll?panel=<https-url>&code=<invite>` + QR + ручная
  вставка. Переиспользует механику `family_invites` (код + max_uses + срок).
  Открытие: клиент добавляет профиль панели, тянет `/app/branding`, ведёт юзера в
  register/login (или login/code из бота). Аккаунт нужен всегда.
- Если подписка не оплачена: панель-настройка **onboarding-трафика**
  `onboarding_traffic_mb` (дефолт 0 = выкл; если задан, новый неоплаченный аккаунт
  получает столько трафика, чтобы подключиться, дойти до Telegram и оплатить).
  Опирается на существующую инфраструктуру `free_plan_daily_traffic`.

### 4.4 Мульти-профиль (клиент)
- Профиль = { id, type: "raw_sub"|"panel_account", display_name, source (URL),
  panel_url?, account/token?, branding_cache?, last_active }. Хранилище профилей,
  переключение активного. Активный профиль задаёт и подключение, и тему.

## 5. Протоколы (Q2: все актуальные)

Импорт сырых подписок и сборка mihomo-конфига должны покрывать актуальный набор:
VLESS (Reality / WS / HTTPUpgrade / gRPC / TCP), VMess, Trojan, Shadowsocks (+
ShadowTLS), Hysteria2, TUIC v5, AmneziaWG / WireGuard, NaiveProxy. Форматы
импорта: clash/mihomo YAML, sing-box JSON, v2ray base64-список, и одиночные URI
`vless://`/`vmess://`/`trojan://`/`ss://`/`hysteria2://`/`tuic://`/`wireguard://`.
mihomo нативно умеет это; задача — парсеры импорта + проверка маппинга в
`profile` + выбор протокола в UI. AmneziaWG уже прошит (см. `docs/AMNEZIAWG.md`).

## 6. Соответствие сторам (Q5)

Цель — пройти Apple App Store и Google Play. Ориентир: в сторах живут Hiddify,
Streisand, v2rayNG, Shadowrocket, FoXray (config/subscription-клиенты). Правила:
- Никакой динамической загрузки исполняемого кода. Подписки — это ДАННЫЕ конфига,
  не код. Никаких удалённых патчей логики.
- Корректные VPN-права: iOS/macOS Network Extension (Personal VPN entitlement),
  Android `VpnService` + обоснование `FOREGROUND_SERVICE_SPECIAL_USE` в Play.
- Прозрачность: privacy-манифест (iOS), описание сбора данных (Play Data Safety).
  Клиент по умолчанию ничего не телеметрит без согласия.
- Контент: позиционирование как инструмент приватности/обхода цензуры, без
  обещаний анонимности-для-незаконного. Реклама апселла (Free-тир) — собственная,
  не сторонние SDK-трекеры (чтобы не ловить политику рекламных сетей).
- Sideload/AltStore как запас, если ревью завернёт «universal panel client».
Фаза P7 проводит аудит на эти пункты и чинит найденное.

## 7. Пофазная спецификация (порядок исполнения для автономного прогона)

Каждая фаза = отдельный ultracode-workflow recon->build->review->fix. Следующую
фазу запускать только после того, как fix-агент закрыл critical+major находки
ревью. Build-агенты внутри фазы работают по НЕПЕРЕСЕКАЮЩИМСЯ директориям.

### P0 — Ребренд в Caramba Connect + правила
- Цель: пользовательский шелл приложения = «Caramba Connect» (нейтральный дефолт),
  exarobot-строки остаются только там, где это тенант #1. Обновить ANTI-SLOP.md
  (правило наименования из памяти). Завести единый файл констант бренда/тиров.
- Файлы: `apps/caramba-client/lib` (строки/тема дефолта, без правок vpn-ядра),
  `apps/caramba-client/ANTI-SLOP.md`. Review: бренд/анти-слоп + не сломаны ли
  экраны. Acceptance: дефолтный бренд = Caramba Connect, код-иды не тронуты.

### P1 — Универсальный клиент: импорт сырых подписок + мульти-профиль + протоколы
- Build A (Go core): парсеры импорта (clash/sing-box/v2ray/URI) -> внутренняя
  модель -> mihomo-конфиг; покрытие протоколов из §5; тесты. Владеет
  `libs/caramba-core/profile`, новый `libs/caramba-core/subimport` (или аналог),
  `libs/caramba-core/mobile`+`ffi` (метод import). НЕ трогает панель/клиентский UI.
- Build B (Flutter): модель профиля + хранилище + переключатель активного
  профиля + экран импорта (вставка URL/QR/файл). Владеет `apps/caramba-client/lib/
  state`, `lib/features/profiles` (новый), `lib/data/models`. НЕ трогает vpn-канал.
- Build C (Flutter vpn-wire): активный профиль -> `configure`/connect (raw-sub vs
  panel-account). Владеет `apps/caramba-client/lib/vpn`, `lib/state/providers.dart`.
- Review: контракт импортных форматов, корректность маппинга протоколов, что
  мульти-профиль не ломает текущий single-panel-поток. Acceptance: можно
  импортировать сырую подписку и подключиться без аккаунта (на моке/статике).

### P2 — Подключение к панели: enrollment-ссылка + onboarding-трафик
- Build A (панель): диплинк-обработка не нужна на сервере, но нужен invite ->
  enrollment контракт + onboarding-трафик. Миграция `onboarding_traffic_mb`
  (настройка) + логика выдачи неоплаченному аккаунту. Владеет
  `apps/caramba-panel/src/api/v2` (enrollment/onboarding), `services`,
  `libs/caramba-db/migrations`. Переиспользует family_invites +
  free_plan_daily_traffic.
- Build B (Flutter): обработка `carambaconnect://enroll`, добавление панель-
  профиля, register/login/login-code, показ onboarding-трафика. Владеет
  `apps/caramba-client/lib/features/auth`, `lib/router`, `lib/features/profiles`.
- Review: безопасность enrollment (одноразовость/срок/привязка), что onboarding
  не раздаёт трафик бесконечно, контракт клиент<->панель. Acceptance: по ссылке
  заводится панель-профиль, неоплаченный юзер получает onboarding-трафик.

### P3 — White-label брендинг (тир-гейт) + апселл на Free
- Build A (панель): `GET /app/branding` + хранение настроек бренда оператора +
  гейт по тиру (Free -> enabled:false, upstream_ads:true). Поверхность настройки
  бренда: добавить в бот-админку команды + (минимальный) конфиг; решение зафикс. в
  P3 recon (веб-админа в репо, похоже, нет). Владеет `apps/caramba-panel/src` +
  миграция бренд-настроек + `apps/caramba-bot` (админ-команды бренда).
- Build B (Flutter): слой темизации от активного панель-профиля (имя/лого/акцент в
  рамках анти-слопа), дефолт Caramba Connect, промо-блок апселла когда
  upstream_ads. Владеет `apps/caramba-client/lib/theme`, `lib/features` (брендовые
  поверхности). Review: тир-гейт реально закрывает брендинг на Free; анти-слоп
  держится даже на операторском акценте; апселл показывается только на Free.

### P4 — Лицензирование + тиры + активация + инсталлер
- Build A (control plane): тонкий лиценз-сервер (новый bin-crate или режим), выдача
  и проверка ключей (ed25519-подпись), эндпоинт activate из §4.1. Владеет новым
  крейтом, напр. `apps/caramba-license` + `Cargo.toml` workspace.
- Build B (панель): активация при старте + периодически, кеш + грейс офлайн,
  enforcement матрицы лимитов (ноды/юзеры/биллинг/брендинг/ads/manual-approval).
  Free не требует ключа. Владеет `apps/caramba-panel/src` (license-модуль,
  enforcement в node/billing/branding путях) + миграция license_state.
- Build C (инсталлер): приём лицензионного ключа на установке + генерация
  instance_id + запись в env/конфиг. Владеет `apps/caramba-installer`.
- Review: грейс не блокирует живых юзеров; Free реально не может включить биллинг и
  добавить 3-ю ноду; подпись лицензии проверяется; ключ нельзя тривиально подделать
  офлайн. Acceptance: тиры различимы и enforced статически по коду.

### P5 — Бот на инстанс
- Цель: бот берёт (токен + URL панели) из конфига; exarobot = один конфиг. Убрать
  оставшиеся хардкоды exarobot из user-facing бот-копий там, где это платформенный
  текст (тенант-специфика остаётся настройкой). Владеет `apps/caramba-bot`.
  Review: бот не завязан на один URL/бренд; код-иды целы.

### P6 — exarobot как org #1 (бэкфилл, не сломать прод)
- Цель: завести дефолтный org и привязать существующих юзеров/ноды/подписки;
  exarobot = tenant #1. Миграция бэкфилла идемпотентная. Владеет
  `libs/caramba-db/migrations` + `apps/caramba-panel/src` (org-привязки там, где
  лимиты/брендинг этого требуют). Review: 20 живых юзеров продолжают работать,
  миграция безопасна и обратимо-нейтральна.

### P7 — Аудит под сторы + докуы + честный список
- Цель: пройтись по §6 (права VPN, отсутствие динамического кода, privacy-
  манифест/Data Safety, апселл без сторонних трекеров), починить найденное;
  обновить `INTEGRATION.md`/`RUNNING.md`/`BUILDING.md`; написать
  `docs/CARAMBA-CONNECT-STATUS.md` с честным разбором: что сделано статически и что
  ТРЕБУЕТ живых тулчейнов/железа/подписи/хостинга лиценз-сервера. Review: полнота
  аудита.

## 8. Операционные правила автономного прогона

- Бренд: user-facing = Caramba Connect (дефолт) / exarobot (тенант #1) / per-tenant
  (настройка); код-иды = caramba; CarambaSelector="CARAMBA" не трогать.
- Анти-слоп: нет фиолета/градиентов/глассморфизма; цвет = только статус подключения;
  иконки Lucide (не эмодзи); моно только для тех-данных; БЕЗ em-dash в user-facing
  строках и прозе доков (em-dash ок только в код-комментариях); без слоп-слов.
- Статик-онли: ничего не компилировать/биндить/запускать. Код compile-ready под
  стиль репозитория. Панель = источник истины контрактов.
- Паттерн фазы: recon (read-only) -> build (непересекающиеся директории) ->
  состязательное ревью (минимум 2 линзы: логика/контракт + бренд/анти-слоп; для
  лицензий добавить линзу безопасности) -> fix (закрыть critical+major). Следующую
  фазу запускать только после закрытия критичных находок.
- В промптах-шаблонах workflow избегать обратных кавычек.
- В конце каждой фазы — короткий лог, в самом конце — отчёт `CARAMBA-CONNECT-
  STATUS.md` + обновление памяти (`caramba-connect-platform`).

## 9. Финальный честный список (обязателен в конце)

Прогон статический. В финале явно перечислить, что требует пользователя:

подпись iOS/macOS (Apple developer, Network Extension) + Android VPN consent +
Play обоснование FOREGROUND_SERVICE_SPECIAL_USE; хостинг лиценз-сервера + генерация
ed25519-ключей; ноды оператора (свои) с актуальными протоколами, для AmneziaWG —
AmneziaWG-совместимый сервер на ноде; публикация в сторах (ревью-риск universal
client) + sideload как запас.
